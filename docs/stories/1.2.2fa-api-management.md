### Data Models
[Source: architecture.md#data-models]
- **TwoFactorAuth**: 双因素认证配置表
  - `user_id`: 用户ID (外键)
  - `secret_key`: TOTP密钥 (加密存储)
  - `qr_code_url`: 二维码URL
  - `is_active`: 激活状态
  - `created_at`, `verified_at`: 时间戳
- **TwoFactorBackupCode**: 备用恢复代码表
  - `user_id`: 用户ID (外键)
  - `code_hash`: 代码哈希值
  - `is_used`: 使用状态
  - `created_at`, `used_at`: 时间戳

### API Specifications
[Source: architecture.md#rest-api-specification]
基于现有API设计模式，新增端点应遵循以下规范：
- **请求格式**: JSON
- **响应格式**: 统一的响应结构 `{code: int, message: string, data: object}`
- **认证方式**: Bearer Token (JWT)
- **错误处理**: HTTP状态码 + 错误详情

具体端点规范：
1. `POST /api/admin/auth/enable-2fa`
   - 请求：无需参数
   - 响应：`{qrCodeUrl: string, secret: string}`

2. `POST /api/admin/auth/verify-2fa-setup`
   - 请求：`{code: string}`
   - 响应：`{backupCodes: string[]}`

3. `POST /api/admin/auth/disable-2fa`
   - 请求：`{password: string}`
   - 响应：`{success: boolean}`

4. `GET /api/admin/auth/2fa-backup-codes`
   - 响应：`{codes: string[], usedCount: int}`

5. `POST /api/admin/auth/regenerate-backup-codes`
   - 请求：`{password: string}`
   - 响应：`{codes: string[]}`

6. `GET /api/admin/auth/2fa-status`
   - 请求：无需参数
   - 响应：`{enabled: boolean, verifiedAt: string}`

### Technical Constraints
[Source: architecture.md#technical-summary]

- **数据库**: MySQL 8.0+
- **缓存**: Redis (用于会话管理)
- **安全**: JWT认证 + TOTP双因素认证

- 权限控制：确保用户只能管理自己的2FA设置
- 审计日志：记录所有2FA相关操作
