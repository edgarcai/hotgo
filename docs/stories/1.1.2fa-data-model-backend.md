## Dev Notes

### 项目结构信息
[Source: architecture.md#High Level Architecture]
- 后端代码位于 `server/` 目录
- 采用分层架构：API层、业务逻辑层、数据访问层、数据模型层
- 基于 GoFrame v2.9.1 框架
- 数据库：MySQL + Redis

### 数据模型设计
[Source: architecture.md#Data Models]
基于现有的用户表结构，需要创建以下新表：

```sql
-- 双因素认证主表
CREATE TABLE user_two_factor (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    secret_key VARCHAR(255) NOT NULL,
    qr_code_url TEXT,
    is_active BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    verified_at DATETIME NULL,
    FOREIGN KEY (user_id) REFERENCES user(id) ON DELETE CASCADE,
    UNIQUE KEY uk_user_id (user_id)
);

-- 备用恢复码表
CREATE TABLE user_two_factor_backup_codes (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    code_hash VARCHAR(255) NOT NULL,
    is_used BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    used_at DATETIME NULL,
    FOREIGN KEY (user_id) REFERENCES user(id) ON DELETE CASCADE,
    INDEX idx_user_id (user_id)
);
```

### 技术实现要求
[Source: prd.md#技术约束和集成要求]
- 遵循 GoFrame 框架的分层架构模式
- 文件位置：`internal/logic/auth/twofa/`, `internal/model/entity/`, `api/admin/auth/`
- 命名约定：使用`TwoFA`或`twofa`前缀
- TOTP实现必须符合RFC 6238标准
- 密钥和备用码必须加密存储

### TOTP实现规范
[Source: prd.md#非功能需求]
- 验证码时间窗口：30秒
- 支持30秒的时钟偏移容错
- 密钥长度：32字节（Base32编码）
- 验证码长度：6位数字

### 安全要求
[Source: prd.md#技术约束和集成要求]
- 密钥使用AES-256加密存储
- 备用码使用bcrypt哈希存储
- 所有敏感操作记录安全日志
- 实现防暴力破解机制

### 性能要求
[Source: prd.md#非功能需求]
- 2FA验证过程应在3秒内完成响应
- 支持至少1000个并发用户同时进行2FA验证
- 新表设计不应影响现有查询性能

### 依赖的Go包
基于GoFrame项目结构，需要使用：
- `github.com/gogf/gf/v2` - GoFrame核心框架
- `github.com/pquerna/otp` - TOTP实现
- `golang.org/x/crypto/bcrypt` - 密码哈希
- `crypto/aes` - AES加密
- `encoding/base32` - Base32编码
